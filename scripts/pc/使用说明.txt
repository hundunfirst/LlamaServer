Bonsai 本地模型 —— 傻瓜式使用说明
====================================

这个文件夹可以整体搬走
----------------------
整个文件夹（llama\ models\ 和这几个文件）可以剪切到桌面、D 盘、U 盘，
所有路径都是相对的，换位置不影响。

注意：搬之前先把黑窗口关掉（服务在跑会占用文件）；桌面若在 OneDrive 下会被上传。

第一次用（三步）
----------------
  1) 双击 启动Bonsai.bat
  2) 菜单里输入序号选模型 -> 回车
  3) 等窗口出现 listening on http://0.0.0.0:8081，浏览器打开 http://127.0.0.1:8081/
     停止：关闭黑窗口，或按 Ctrl+C

菜单会自动配对：
  - 视觉：同系列的 *-mmproj-*.gguf
  - 投机解码：主模型自带 MTP 头就自动启用；外部草稿只在菜单里提示，要手动指定
  草稿/侧车文件永远不会被列成"主模型"。

关于控制台输出
--------------
  llama-server 的日志绝大多数是正常信息（默认色），黄色是警告，红色才是真错误。
  之前整屏泛红是启动脚本多接管了一层输出导致的，已修好。

参数都在 start-bonsai.ps1 顶部：
  端口 / 上下文（0=按模型大小自动）/ GPU层数 / 线程 / 监听地址 / 令牌 /
  投影器放内存 / 是否用内置 MTP / 草稿预测长度

自动上下文参考（4GB 显存）
  2B 及以下 32768，3B~8B 16K，8B 以上 4096，20B 以上 2048

一键启动某个模型（不经过菜单）
------------------------------
建个快捷方式，目标填：
    "C:\...\启动Bonsai.bat" -Model "Ternary-Bonsai-2-9B-PQ2_0-MTP-Q8_0.gguf"
可选参数：
    -Projector none       不用视觉
    -Draft none           关闭投机解码（纯基线，用来对比速度）
    -Draft mtp            强制用主模型内置 MTP 头
    -Draft "xxx.gguf"     指定外部草稿文件
    -Ctx 8192             强制上下文（0 = 自动）

关于"草稿"文件（投机解码）
--------------------------
  *-DFlash2-* / *-dspark-* / *-MTP-Q8_0.gguf 这类是给主模型加速的草稿，
  单独当主模型加载会失败（dflash requires ctx_other to be set）。
  而且草稿必须和主模型"同一血统"：实测 9B 的 DFlash2 草稿配 9B PQ2_0-MTP 主模型
  会报 invalid vector subscript 直接崩，所以默认不自动启用，只在菜单里提示。

  实测（RTX 2050 4GB，本机）：
    4B PQ2_0，上下文 8192              ~64 tok/s
    9B PQ2_0-MTP，上下文 4096，无投机    ~40 tok/s
    9B PQ2_0-MTP，上下文 4096，开 MTP    ~55 tok/s（快 36%，草稿命中率 68%）

在手机上用（可选）
------------------
  1) HOST_ADDR 保持 0.0.0.0，APIKEY 填一个只有你知道的字符串
  2) 电脑和手机连同一个 WiFi，ipconfig 看 IPv4 地址
  3) 手机 App -> 设置 -> 模型渠道 -> 新增：
        地址：http://192.168.31.132:8081
        密钥：和 APIKEY 一样
        模型：随便填（比如 local）

想让它能看图（视觉）
--------------------
  主模型和投影器都放 models\ 里，菜单自动配对；投影器文件名一定带 mmproj，
  且必须同尺寸（4B 配 4B，9B 配 9B）。显存紧张时保持 MMPROJ_ON_CPU = 1。

出问题了
--------
  * 提示找不到模型        -> 看 models\ 里文件名
  * 提示地址已被占用      -> 端口改成 8082、8083
  * 启动一半退出、提示显存 -> 上下文调小（-Ctx 2048），或 GPU层数 NGL 调小（99->20->0）
  * 想看每个文件是什么    -> powershell -ExecutionPolicy Bypass -File start-bonsai.ps1 -Diagnose
  * 想看会执行什么命令    -> 同上参数换成 -DryRun
  * 双击后窗口一闪而过    -> 同目录 error.log 里有失败原因
