# 超级智能体：下一阶段方案

> 面向手机端本地模型（0.8B–4B）的自主 agent。前提是承认硬件边界：算力、内存带宽、发热都
> 比桌面差一到两个数量级。所以这里的「超级」不指模型多聪明，而是**在弱模型上把任务做完**。

## 一、现在手里有什么

| 能力 | 现状 | 位置 |
|---|---|---|
| 本地引擎 | llama.cpp，CPU/NPU(Hexagon)，0.8B 37 tok/s、4B 预填 625 tok/s | `ServerProcessManager` |
| 工具 | bash、文件读写改搜、网页搜索、沙箱自检、文档生成、OCR、MCP | `core/*Tool*` |
| 审批 | 危险命令/写文件前确认，三档权限（仅查看/工作区/完全） | `ToolGuard` |
| 计划模式 | 只出计划不执行，一键「按计划执行」 | `ChatViewModel` |
| 任务快照 | goal / rounds / todos / lastError / stopped，可续跑 | `ChatStore.TaskState` |
| 编排 | 技能（单步提示词）、技能链（固定多步） | `AppSettings`、`SkillChainFlow` |
| 记忆 | 长期记忆（用户偏好，全局共享） | `MemoryStore` |

缺的是四件事：**排队**、**自驱**、**可撤销**、**经验沉淀**。

## 二、分阶段

### 阶段 1：让它可信——可撤销 + 任务队列

没有撤销的自主等于赌博。手机上一旦让它连跑十步改文件，用户没法一个个回滚。

- **写入快照**：每次 `file_write` / `file_patch` 前把旧内容按路径存进 `files/snapshots/<会话>/`，
  保留最近 N 版；产物卡上加「撤销这次写入」。
- **任务队列**：`TaskQueue`（落盘），多条目标排队，同一时刻只跑一条，跑完发通知。
  现在一次只能跑一个任务，用户在车上想出三件事，只能记在备忘录里。
- 验收：连改三个文件后能一键回到执行前；排队两个任务，前一个跑完自动开始下一个。

### 阶段 2：让它自驱——目标循环

现在的循环是「模型不再调工具就结束」，那是**回合制**，不是目标制。

- **自评判据要客观**：小模型的自我评价不可靠，所以优先接入外部信号——编译是否通过、
  测试是否绿、HTML 是否在沙箱里无报错、文件是否存在且非空。有客观信号就不问模型「你觉得完成了吗」。
- **循环结构**：目标 → 计划 → 执行一步 → 用客观信号判定 → 未达成则修正重试（带轮次、
  时间、token 三重上限）→ 达成或触顶则汇报。
- **与计划模式打通**：计划模式产出的计划，用户批准后转成「自驱任务」，中间不再逐条询问，
  只在需要跨越权限档位时打断。
- 验收：给它「把这个目录里的 csv 汇总成一个 xlsx」这种需要多步试错的任务，能自己跑完或明确报告卡在哪。

### 阶段 3：让它变强——经验沉淀

弱模型的短板是每一步都要重新想。把走过的路固化成资产：

- 成功的多步流程结束时生成**技能草稿**（工具序列 + 关键参数 + 触发条件），用户确认后入库。
- 新目标先检索已有技能（关键词 + 向量都可，先用关键词，手机端够用），命中则套用再微调。
- 这条路比「换更大模型」便宜得多，也是手机上唯一现实的「越用越强」。

### 阶段 4：让它主动——事件触发

- 定时任务（每天/每周）：复用阶段 1 的队列。
- 系统事件：通知、剪贴板、日程、位置。**默认全关**，逐个由用户开启，且只在本地处理。
- 主动性的代价是打扰与隐私，所以这一阶段的验收标准是「可预期」而不是「更聪明」。

### 阶段 5：让它分工——规划/执行分离

我们已经有会话级端点：一条会话可以绑本地、另一条绑云端。

- **规划用云端、执行用本地**：云端大模型出计划和判据，本地小模型照着改文件和跑命令。
  长上下文理解交给云端，隐私数据和文件操作留在手机上。
- 这是相对纯云端 App 的差异化：**数据和副作用不出设备，只有「怎么想」借用云端**。

## 三、三个必须先想清楚的风险

1. **小模型自评不可靠**：所以判据要外置（编译/测试/文件状态），不能让模型自己说「我完成了」。
2. **发热与续航**：自驱循环必须能暂停、限速、在屏幕关闭时降频；长任务默认不连续占用 NPU。
3. **权限膨胀**：自主模式下用户会倾向开「完全权限」，而这正是最容易出事的一档。
   对策是「批量操作的聚合审批」：一次批准整个计划的写入范围，而不是逐条放行导致用户闭眼点。

## 四、第一步（建议下周就做）

只做两件，都是低风险的加法：

1. `file_write`/`file_patch` 的**写入快照 + 撤销**（约 150 行，不动现有工具语义）。
2. `TaskQueue` 的最小版本：内存队列 + 单一 worker + 完成后通知（先不落盘）。

这两件做完，「让它自己跑」才有底气；其余阶段都建立在这个信任基础上。
